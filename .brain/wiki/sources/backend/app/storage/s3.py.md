# backend/app/storage/s3.py

**Role.** The production media storage implementation: mints browser-direct POST upload policies that S3 itself enforces (exact key, exact content type, exact byte count), signs attachment-forcing GET URLs, and runs head/read/delete off the event loop — mapping every botocore failure to one of two typed errors that carry no AWS text.

**Module.** [[backend/app/storage/_index]] · **Layer.** platform

## Public Surface

| Symbol | Kind | Purpose |
|---|---|---|
| `S3MediaStorage` | class | `MediaStorage` implementation over boto3; constructed from [[backend/app/core/config.py]]'s `Settings` |
| `S3MediaStorage.presigned_post` | method | POST policy pinning key, `Content-Type` and an exact `content-length-range` |
| `S3MediaStorage.signed_get_url` | method | Presigned GET with `ResponseContentType` + `attachment` disposition overrides |
| `S3MediaStorage.head_object` | method | `ObjectHead` or `None`; a genuine miss is `None`, an outage raises |
| `S3MediaStorage.read_prefix` | method | Ranged GET of the first `length` bytes (magic-number sniffing) |
| `S3MediaStorage.delete_object` | method | Best-effort delete, same error mapping |
| `_MISSING_OBJECT_CODES` | const | `{"404", "NotFound", "NoSuchKey"}` — the only codes that mean "not there" |
| `_is_missing_object` | fn | Reads both the error `Code` and the HTTP status, because HeadObject has no body |
| `S3MediaStorage._mapped_errors` | contextmanager | Credentials errors → `MediaNotConfiguredError`; everything else → `MediaStorageUnavailableError` |

## Behavior

`__init__` copies four settings fields and does **nothing else** — no network I/O, no credential resolution. That is deliberate: building a botocore client walks the whole provider chain, whose last providers read `~/.aws` and call IMDS over the network, so an eager client would make `create_app()` unsafe to call in the fast suite depending on what the developer's machine happens to hold. The client is built lazily in `_s3()` on first use. Inside `_s3()` sits the file's real bug history: `generate_presigned_post()` builds its form `url` from the client's `endpoint_url`, not from `region_name`, so leaving `endpoint_url` unset let botocore fall back to the legacy global `bucket.s3.amazonaws.com` host — which AWS opt-in regions, `il-central-1` among them, reject with `IllegalLocationConstraintException`. The fix always resolves a concrete `https://s3.<region>.amazonaws.com` endpoint. Its documented side effect: an explicit `endpoint_url` makes botocore address the bucket path-style regardless of `media_force_path_style`, so that flag no longer decides the URL shape here.

`presigned_post` is a POST policy rather than a PUT because only POST makes S3 enforce the exact key **and** the exact `Content-Type` **and** a length range server-side. The range is `[exact_bytes, exact_bytes]` — both bounds equal — so an object whose size differs from the row that authorised it cannot exist. Two omissions are load-bearing: no `acl` field (the bucket is bucket-owner-enforced, where ACLs are disabled and an `acl` field makes S3 reject the POST outright) and no server-side-encryption condition (encryption is a bucket property; pinning the header would break every S3-compatible target). `signed_get_url` carries the sniffing defense: S3 cannot emit `X-Content-Type-Options` on a presigned GET, so the `ResponseContentType` override plus an `attachment` — never `inline` — disposition is what stands in. `attachment` is ignored for subresource loads, so `<img src>` still renders, while a top-level navigation to a polyglot object downloads instead of executing.

Error containment runs through `_mapped_errors`, which re-raises `from None` so the original never renders in a traceback — an AWS message can name the bucket, the account and the full key. Missing or partial credentials become `MediaNotConfiguredError`, collapsing "no bucket" and "bucket with unusable credentials" into one 503; every other `ClientError`/`BotoCoreError` becomes `MediaStorageUnavailableError`. One `logger.warning` line records the operation and the storage key, and because the key embeds `tenant_id`, `dress_id` and `media_id`, that single line correlates the failure with the row that caused it. `head_object` alone reads `_is_missing_object` before the mapping, and it checks both the error code and the raw HTTP status because HeadObject has no response body to carry `NoSuchKey`; a 500, a throttle or a timeout is therefore an outage and never reported to the caller as "your upload never arrived". The three network methods wrap the blocking boto3 call in `anyio.to_thread.run_sync` so the event loop is never blocked.

## Notes

AWS credentials are deliberately **not** `Settings` fields — boto3 reads them from the process environment, so they never enter the config object, never appear in a repr and never get logged. Only bucket/region/endpoint identity lives in settings.
