# frontend/packages/ui/src/__tests__/A11y.test.tsx

**Role.** Two tests, one per export of [[frontend/packages/ui/src/components/A11y.tsx]], pinning the only two facts about them that jsdom can see: `SkipLink` is a real anchor whose `href` reaches the fragment it was given, and `VisuallyHidden` content stays in the accessibility tree rather than being removed from it.

**Module.** [[frontend/packages/ui/src/__tests__/_index]] · **Layer.** test

## Contract Pinned

| Assertion | Why it matters |
|---|---|
| `SkipLink` is queryable by `role="link"` with its Hebrew text as accessible name, and carries the exact `href` passed in | IS 5568 / WCAG 2.4.1 bypass-blocks. If it ever became a `<button>` + `scrollTo`, the role query fails — which is the point. |
| `VisuallyHidden` children are found by `getByText` | `sr-only` must hide *visually*, never from AT. `display:none` or `hidden` would pass a naive snapshot and fail this. |

## Behavior

The `SkipLink` test asserts through the accessibility tree (`getByRole("link", { name })`), not the DOM, so the assertion holds only while the element is a genuine anchor with a discernible name. The `VisuallyHidden` test is the inverse guard: `getByText` in Testing Library ignores nothing about `sr-only` (a clip-based hide) but *would* miss `display:none`, so the test distinguishes the correct hiding technique from the wrong one.

What this file cannot cover is the part that actually bites: `SkipLink`'s focus-only padding. The component's own comment records that a plain `px-4/py-2` overrides `sr-only`'s `padding:0`, leaving a ~64px invisible box that inflates `scrollWidth` and trips the horizontal-overflow check. That is a layout fact jsdom does not compute — it lives in the Playwright reflow spec ([[frontend/e2e/a11y.spec.ts]]), not here. Reading this file as "SkipLink is covered" is the trap.

Both strings under test are Hebrew, matching the RTL-first product; no `dir` is asserted because neither component sets one.
