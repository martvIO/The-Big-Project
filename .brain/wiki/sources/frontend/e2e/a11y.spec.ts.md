# frontend/e2e/a11y.spec.ts

**Role.** The **API-is-down pass**: eight specs that intercept nothing, so both apps are exercised exactly as a visitor meets them when the backend is unreachable. It is also the only place the two apps are checked *together* (the pinch-zoom sweep) and the only place [[frontend/apps/manage/src/components/LoginForm.tsx]]'s screen is audited at all, because with no backend the console can never get past login.

**Module.** [[frontend/e2e/_index]] · **Layer.** test

## Behavior

**Nothing here calls `page.route`, and the file's header says so deliberately.** `vite preview` forwards `/storefront/*` to `:8000`, where either nothing is listening or a backend that has never heard of `localhost` answers `404 TENANT_NOT_FOUND` — to the visitor both are the same event, the boutique's data never arrives. Which one happens depends on the machine, so no assertion pins the exact sentence; the Hebrew-only test pins the *copy contract* instead. [[frontend/e2e/storefront.spec.ts]] covers the same routes with data behind them.

The Hebrew-only assertion is the sharpest thing in the file and the one an axe scan can never see: every backend message is English ("No active boutique at this address.", "Too many attempts. Try again later."), so failure copy must be selected by the error **code** and rendered from the Hebrew bundle. The regex pair — `toMatch(/[֐-׿]/)` and `not.toMatch(/[A-Za-z]{4,}/)` — is what catches a UI that paints the server's sentence onto a Hebrew-only page.

**The two branding tests encode F30's split** ([[.planning/specs/modryn-branding.md]]): MODRYN brands the *platform*, not the tenant. The storefront is the boutique's own shop front and may carry no platform mark beyond the favicon, so its title is asserted **not** to contain "MODRYN". The console *is* the platform, so its title must start `MODRYN — ` and its login lockup is the h1 — with the mark `alt=""` and the Latin wordmark `aria-hidden`, so the accessible name is the Hebrew sentence and "MODRYN" is not announced twice.

Three of these tests exist because of a specific defect class rather than a rule in the abstract. The pinch-zoom test sweeps **both** `index.html` files because they are edited independently, and it rejects `maximum-scale=1` as well as `user-scalable=no` — the former blocks WCAG 1.4.4 resize just as completely while reading as harmless. The woff2 test waits on `document.fonts.ready` **and** `networkidle` before asserting, because `font-display: swap` fetches the Hebrew subset asynchronously and a Latin-only fetch would otherwise look like a pass. The reduced-motion assertion is measured on the retry **Button** — the only element in the error state that declares a transition at all; the note in the file records that the previous form (`["0s", "0.001ms", ""].some(v => duration.includes(v))`) could not fail, because every string contains `""`, and it was being run against an `h1` that has no transition to disable.

The skip-link check asserts the *landing*, not just the focus ring: after Enter, `document.activeElement` must be `{tag: "MAIN", id: "content"}`. An outage costs the page its collection, never its keyboard entry point.

## Notes

The two manage tests can only ever see the login screen. Any console surface behind auth — the bookings board, the catalog editor, the staff table — is covered by component tests under `frontend/apps/manage/src/__tests__/`, never here, and an "add a manage axe scan" instinct will hit a login form unless a backend is stood up first.

The Hebrew-range regex `[֐-׿]` appears in four assertions across this file and in [[frontend/e2e/storefront.spec.ts]]; it is written inline every time rather than hoisted into a shared constant.
