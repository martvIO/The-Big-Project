# frontend/apps/manage/src/__tests__/i18n.test.ts

**Role.** The proof that every dotted-literal copy key F15 (bookings) and F51 (staff) added actually *resolves* through i18next — plus two mechanical register checks over the Hebrew values and a completeness check over the Arabic bundle.

**Module.** [[frontend/apps/manage/src/__tests__/_index]] · **Layer.** test

## Public Surface

| Symbol | Kind | Purpose |
|---|---|---|
| `entries(bundle, match)` | helper | filters a translation bundle to the `[key, value]` pairs whose key matches and whose value is a `string` (skips nested objects) |
| `HE_F15` / `HE_F51` / `HE` | const | the two feature decks, kept **separate** on purpose, and their union |
| `F15 keys resolve` | suite | deck size, per-key resolution, nav item, three-segment error key, interpolation |
| `F51 staff keys resolve` | suite | deck size, the seventh nav item, four error codes, name interpolation |
| `the register, mechanically` | suite | no `!`, and no string that claims/promises/hedges a send |
| `the ar bundle` | suite | no empty string; carries every key `he.ts` has |

## Behavior

Console copy is transcribed into `he.ts` as **dotted literal keys** (`"booking.error.SLOT_UNAVAILABLE"`), one per row of the feature's `copy.md`, sitting in the same bundle as the older *nested* namespaces. That only works because i18next's `ignoreJSONStructure` defaults to `true`: when the nested path misses, it retries as a flat lookup. This suite is the guard on that, and the failure it prevents is loud — an unresolved key renders the **key itself** into the console, so a bride-facing screen would show `booking.error.SLOT_UNAVAILABLE` in Latin text on an RTL page. `nav.bookings` and `nav.staff` are called out individually because each is a flat literal sitting *beside* a nested `nav` object — the exact collision `ignoreJSONStructure` exists to resolve.

**The two deck constants are deliberately not one widened filter.** F15's floor asserts its own deck is whole (`> 70`); folding F51's ~29 keys into the same list would let F15's 76 rows shrink by 29 and still pass — a guard that quietly stops guarding.

The register suite mechanises `copy.md` §0 rules 1 and 2 over the Hebrew values: no exclamation mark anywhere, and nothing matching `/נשלח|תישלח|בדרך/`. For F51 rule 2 is literally true — there is no mailer and no SMS sender ID, so the owner speaks the new password herself. The source comment records why the notice is phrased «יש למסור…» rather than «אינה נשלחת…»: the latter *contains* נשלח and would trip this very guard, and copy that has to dodge its own guard is one edit from lying.

The `ar` bundle checks are the mirror image. i18next's `returnEmptyString` default renders `""` rather than falling back to Hebrew, so an empty Arabic placeholder would **blank the page** instead of degrading. The empty-string filter is typed `Object.entries<string>` on purpose: with the literal types `as const` gives, tsc would call the `=== ""` comparison unreachable and the guard would be dead the day someone actually adds an empty value.

## Notes

`packages/ui` components never call i18n — strings arrive as props — so this suite is scoped to the console's own bundle and can never cover a UI-package string. The numeric floors (`> 70`, `> 25`) are ratchets: raise them when a feature adds keys, never lower them.
