## 0. How to read this plan

Every task is **one TDD cycle and one commit**: the named failing test first, then the code that makes it pass. A dying builder loses uncommitted work (`.memory/builder-agents-must-commit-per-task`), so **every task below leaves the tree importing, collecting and green on its own** — commit before starting the next one, no batching. Three tasks are deliberately larger than their neighbours because their halves cannot be green apart; each says so in its row.

Order: schema → pure rules → the tenant setting → service → routes+walkers → frontend helpers → wire → copy → components → nav → e2e. Frontend components come after the copy deck so every component test asserts real Hebrew rather than a key echo.

Spec D1–D13 and design F-1…F-23 are binding and not restated. Everything in §1 was verified against `main` on 2026-08-10.

## 2. Migration `NNNN_shift_availability.py` — **NNNN is resolved at build time, not now**

⚠ **Do not write a number into this file from this plan.** The observed head on `main` is `0033`; **F26 holds `0034` in `.worktrees/invite-signup` and will very likely merge first**, and other worktrees may open behind it.

**At build time**, in the F39 worktree, after branching from a fresh `origin/main`:

```
cd Backend && uv run alembic heads      # must print exactly ONE head
```

Take that head + 1 for the filename, `revision`, and `down_revision` = the observed head. If `alembic heads` prints **two** heads before you have written anything, stop — main is already branched and that is a bigger problem than this feature.

**Then re-resolve immediately before the pre-push rebase — this is the step that gets skipped.** See §6's renumber protocol; it is not optional and it is not the same act as the first resolution.

Contents, raw SQL, `0031` copied in every particular (`_STANDARD`, `_updated_at_trigger`, `GRANT SELECT, INSERT, UPDATE, DELETE … TO app_user`, `enable_tenant_rls`): the spec's two `CREATE TABLE` blocks verbatim — `shift_templates` with `shift_templates_day_check` and `shift_templates_order_check` and `idx_shift_templates_day`; `staff_availability` with `staff_availability_state_check`, `staff_availability_week_start_check`, `idx_staff_availability_unique` (partial, `WHERE deleted_at IS NULL`) and `idx_staff_availability_week`.
