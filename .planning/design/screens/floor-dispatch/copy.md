## 0. The rules this deck is written under — hard constraints, not preferences

1. **Zero exclamation marks** (pre-decided #5). Mechanically checked — `i18n.test.ts:556` filters every value in `HE` for `"!"`. **See §11 for the scan.**
2. **Never claim, promise or hedge that a message was sent, in any tense.** `i18n.test.ts:560` enforces it as `/נשלח|תישלח|בדרך/` over every value in `HE`. **This feature is the one where the guard actually bit** (§7): a cue about a *summons* reached for a *sending* verb, and the summons is a timestamp on a row. F58 sends nothing to anybody.
3. **The panel states, it does not reassure.** Every string is a fact. No «הכל תקין», no «מצוין», no encouragement, no apology. A staffer reads this screen fifty times a shift and warmth at that frequency is noise.
4. **No string names or implies a retry interval.** F34's rule 9, inherited through `usePoll`'s backoff: consecutive failures stretch the interval 5s → ~60s, so «מיד» is true at tick 1 and false by tick 5. Every stale or refused sentence names the **event** («בעדכון הבא»), and its paused twin names the **control that is on screen** («עם חידוש העדכון»), never a duration. **And never an action she cannot take**: «רענני» would name a refresh control that only exists while the panel is stale.
5. **No string names or implies a server-owned limit.** The waiting read is `LIMIT 100` (spec D2) and it is the server's to change without a copy edit. The truncation line says the list is partial and **what falls off**; it carries no number, which rule 4's digit guard would catch anyway.
6. ⚠ **No string may place a Hebrew preposition, article or agreeing verb immediately against `{{room}}`.** A room label is a **user-typed noun of unknown gender that carries its own noun**: the boutique types «חדר 1 / חדר 2 / הבמה», so «לחדר {{room}}» renders **«לחדר חדר 2»** and any «{{room}} נתפס» renders **«הבמה נתפס»**, a gender disagreement against a value no translator can see. This is F36's **F-3**, established as a general rule and violated twice by D16's table (`waitlist.takeNextAria`, `waitlist.dispatchedCue`); both are corrected below. The shapes that survive it, and the only ones this deck uses: **em-dash, value last** («קחי את הבאה בתור — {{room}}») and **colon appositive, value last** («הלקוחה שובצה: {{room}}.»).
   **`{{name}}` is exempt and this is the whole distinction.** A name on this surface is always a woman — the product's persona convention is feminine throughout — so a feminine verb against `{{name}}` agrees by construction, which is why «להסיר את {{name}} מהתור?» is safe.
7. ⚠ **Every `*Aria` value STARTS with its visible label.** `i18n.test.ts:456-468` asserts it for `rooms.*` and WCAG **2.5.3 label-in-name** requires it: a speech-input user says what she can see. **Four of D16's five proposals fail this** — «הסרת {{name}} מהתור» is a *different word form* from «הסרה», and «שבצי את {{name}} לחדר» does not open with «שבצי לחדר». Corrected as a class in §3: every accessible name is `<visible label> — {{value}}`. An `aria-label` takes no markup, so an interpolated value in one needs **no bidi treatment at all** (F57's F-11).
8. **Status is carried by WORDS.** A `Badge`'s colour is reinforcement and never the signal. **No emoji, no dots, no glyphs**: an emoji is announced by a screen reader with a name this product did not choose and cannot translate, and the console ships **no icon vocabulary at all**.
9. **No value is declared twice.** A string reused across panels keeps its original key (§9). This is F36's **F-10** applied before the duplicates exist rather than after — D16 would have added four.
10. **No customer's name enters `role="status"`.** §7, and it is the deck's sharpest privacy line.
11. **Every value is a real string.** No `…`-as-placeholder, no Lorem, nothing to be filled in later.
12. **The `ar` column is the approved Hebrew standing in untranslated** (Interview Q3 / pre-decided #47 / the 2026-07-31 languages ruling) and is **never an empty string**: i18next's `returnEmptyString` default renders `""` rather than falling back, so a premature switch would blank the page instead of showing Hebrew. `lng` stays `"he"`, `fallbackLng` stays `"he"`, **no switcher ships**. The assertion is `ar[key] === he[key]` — **not "non-empty"**, which passes on an English string, a `TODO`, or a *different* Hebrew wording.

## 7. The announced cues — user-initiated only, and NOT ONE names a customer

**The poll never writes into `role="status"`** (F34's D11, verbatim and non-negotiable). A status update every five seconds announces the whole queue forever and makes a screen reader unusable for a whole shift. The region carries **user-initiated outcomes only**, and **a row that appears, moves or vanishes because a colleague acted — or because a woman scanned the QR at the door — repaints silently.** So does every position renumbering.

⚠ **"Write" means write, not change.** Assigning a byte-identical string to a text node still produces a real `childList` mutation inside `role="status"` (F34's **F-7**; `FloorPanel.tsx:236-243` carries the warning). The cue is written **only when its value actually changes**, and the test must drive **several consecutive ticks with the cue already populated** — a single-tick assertion passes against the broken version whenever the cue starts empty.

⚠ **NO CUE IN THIS FEATURE NAMES A CUSTOMER, and D16's first draft had the shipped rule backwards.** `RoomsPanel.tsx:464-469`, verbatim:

> The cue names the ROOM and never the client. The region is **PERSISTENT** — nothing clears it on a timer — so a bride's name in it would sit on a five-role screen for an arbitrary length of time, in a room she is standing in. The tile one line away carries her name for exactly as long as the fitting lasts.

**The rule is about persistence, not about refusals**, and `FloorPanel.tsx:510-521` confirms it: the cue is a plain `<p role="status">` overwritten only by the next cue and cleared by **nothing** — no timer, no tick, no unmount. F58's cues would have been **strictly worse than the case F36 declined**: «נועה הוסרה מהתור.» sits in the DOM of a five-role screen after her row has left the payload **and after she has left the shop**, so the cue becomes the only place her name survives — falsifying spec D10's own rewritten promise that *"every name leaves the payload the moment she does"*, on the surface Risk 4 calls the most legally sensitive line in the spec. **So the cues name the ACT.**

## 8. Interpolations, and which bidi helper each one takes

The two shipped helpers are `isolateLtr` and `isolateBidi` (`lib/booking.tsx`). Each splits a translated string around **one** value and returns a `ReactNode`, so **they cannot be chained** — a sentence carrying two interpolated values has no shipped way to isolate both. That is why **no string in this deck interpolates twice**, and why the meta line is two sibling fragments around a «·» rather than one sentence.

| Value | Kind | Helper | Why |
|---|---|---|---|
| `{{minutes}}` | numeric run | **`isolateLtr`** → `<bdi dir="ltr">` | A digit run inside an RTL sentence. The one string is `waitlist.waiting` |
| `{{room}}` | a user-typed room label | **`isolateBidi`** → bare `<bdi>` | ⚠ **Never `isolateLtr`.** A boutique may type «הבמה» or «VIP Room» and the panel cannot know which; forcing LTR on the first reverses its words. The one rendered string is `waitlist.dispatchedCue` (`rooms.takeNextAria` is an `aria-label`) |
| `{{name}}` | a customer's name | **`isolateBidi`** → bare `<bdi>` | Same reasoning, and it is the value this panel exists to render correctly: `dir="ltr"` on «נועה בר» reverses its words and it is the bidi defect that *looks deliberate* (F57's **F-11**) |
| the row's `name` field | a customer's name, as its own element | **no helper** | It is a bare `<bdi>` in its own node, never interpolated into a sentence — F36's deck-wide rule, *"wherever a value can be its own element, it is"*. **No truncation and no ellipsis, ever**: this is the panel where two abbreviated «נועה»s decide who gets removed |

**Three contexts take NO treatment at all, and each is a different reason:**

| Context | Keys | Why nothing is needed |
|---|---|---|
| `aria-label` | `waitlist.callAria`, `assignAria`, `skipAria`, `removeAria`, `rooms.takeNextAria` | An `aria-label` takes no markup, so there is nothing rendered to reorder. `booking.tsx`'s own comment says so |
| a `Select`'s `label` prop | `waitlist.assignRoom` | ⚠ **Typed `string` (`Select.tsx:6`), so isolation is IMPOSSIBLE, not merely omitted.** The value therefore goes **last**, where a direction flip has nothing after it to reorder past. This is the concrete reason §0 rule 6's em-dash shape is a rule and not a preference |
| the reveal questions | `waitlist.confirmSkip`, `confirmRemove` | ⚠ **These DO interpolate `{{name}}` and DO take `isolateBidi`** — they render as paragraphs, not as props. Listed here so the row above is not read as covering them |
