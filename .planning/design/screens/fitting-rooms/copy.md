## 0. The rules this deck is written under — hard constraints, not preferences

1. **Zero exclamation marks** (pre-decided #5). Mechanically checked — `__tests__/i18n.test.ts:328-330` filters every value in `HE` for `"!"`.
2. **Never claim, promise or hedge that a message was sent, in any tense.** `i18n.test.ts:332-334` enforces it as `/נשלח|תישלח|בדרך/` over every value in `HE`. Trivially satisfied here — the feature sends nothing — and stated anyway, because *"נודיע לעמיתה שהחדר עבר אליה"* is the exact sentence a well-meaning editor would add to the handover cue. **See §10 for the scan.**
3. **The panel states, it does not reassure.** Every string is a fact. No «הכל תקין», no «מצוין», no encouragement, no apology. A staffer reads this screen fifty times a shift and warmth at that frequency is noise.
4. **No string names or implies a retry interval.** F34's rule 9, inherited through `usePoll`'s backoff: consecutive failures stretch the interval 5s → ~60s, so «הרשימה תתעדכן מיד» is true at tick 1 and false by tick 5. Every stale or refused sentence names the **event** («בעדכון הבא»), never a duration. `i18n.test.ts:305-311` already enforces this for `floor.*` as "no digit anywhere except `floor.idleStopped`"; **`floor.statusOccupied` is inside that guard by prefix and carries no digit.**
5. **No string names or implies a server-owned limit.** The dress list is `LIMIT 500` and the client list `LIMIT 200` (spec D16), and both are the server's to change without a copy edit. The two truncation lines say the list is partial and what to do about it; **neither carries a number**, which rule 4's digit guard would catch anyway.
6. ⚠ **No string may place a Hebrew preposition, article, or agreeing verb immediately against `{{room}}` or `{{dress}}`.** These are **user-typed nouns of unknown gender that carry their own noun**. The boutique types «חדר 1 / חדר 2 / הבמה» (spec D1's own example), so «בחדר {{room}}» renders **«בחדר חדר 2»** and any «{{room}} נתפס» renders **«הבמה נתפס»** — a gender disagreement against a value no translator can see. Four of spec D17's proposed strings have this defect (`rooms.occupancyLine`, `rooms.error.STAFF_OCCUPIED`, and both cue shapes); all four are corrected below, and **`design.md` F-3 records it as a general rule rather than four patches.** The four shapes that survive it, and the only ones this deck uses:
   - **em-dash, value last** — «שחרור — {{room}}»
   - **colon appositive, value last** — «החדר נתפס: {{room}}.»
   - **guillemets** — «למחוק את «{{room}}»?» *(used nowhere in the end; see §5.1)*
   - **its own element**, no interpolation at all — `design.md` §3.4's deck-wide rule, *"wherever a value can be its own element, it is"*
   **`{{name}} is exempt and this is the whole distinction.** A name on this surface is always a woman — the product's persona convention is feminine throughout («פנויה», «תפוסה», «בהפסקה», «אשת הצוות») — so a feminine verb against `{{name}}` agrees by construction, which is why «{{name}} נמצאת בחדר עכשיו.» is safe and «{{room}} נתפס» is not.
7. **Status is carried by WORDS.** A `Badge`'s colour is reinforcement and never the signal — F51's shipped rule (*"The WORD carries the role; the colour never does"*) and `FloorPanel.tsx:554` (*"The WORD carries the state; the colour never does"*). **No emoji, no dots, no glyphs**: an emoji is announced by a screen reader with a name this product did not choose and cannot translate, and the console ships **no icon vocabulary at all**, so the first glyph would be a convention with one member.
8. **Reuse F57's and F34's keys wherever this panel says the same thing about the same thing.** The rooms panel lives inside `FloorPanel`'s poll, so it inherits every freshness, pause, idle, stale and terminal state and **must not spell any of them a second way** — spec D17's reuse-before-invention rule and F57's F-10 argument. §9 is the list, and it is 17 rows long.
9. **Every value is a real string.** No `…`-as-placeholder, no Lorem, nothing to be filled in later. There is no `…` anywhere in this deck.
10. **The `ar` column is the approved Hebrew standing in untranslated** (Interview Q3 / pre-decided #47 / the 2026-07-31 languages ruling) and is **never an empty string**: i18next's `returnEmptyString` default renders `""` rather than falling back, so a premature switch would blank the page instead of showing Hebrew. `lng` stays `"he"`, `fallbackLng` stays `"he"`, **no switcher ships**. Spec D17's assertion is `ar[key] === he[key]` for every `rooms.*` key — **not "non-empty"**, which passes on an English string, a `TODO`, or a *different* Hebrew wording.

## 4. The claim's client picker — inline on the free tile, never a dialog

Spec **D16** puts the picker on the tile: no focus trap to write, no return contract to test, no fourth dialog component. One tap if she does not care which bride, two if she does.

⚠ **`rooms.clientPick` is a `Select` LABEL, not a placeholder.** `@boutique/ui`'s `Select` requires `label: string` (`Select.tsx:6`) and wires `useId()` → `htmlFor`; the label is a **required prop** and must carry an approved string rather than being invented at build time. **The visible label carries the room, and that is what disambiguates up to six identical pickers** — four `<select>`s all labelled «לקוחה» is a screen-reader dead end at exactly the moment the panel is busy. Putting the room in the *visible* label makes the accessible name **be** the visible label, so 2.5.3 is satisfied by construction rather than by an assertion, and it costs no second key and no `aria-label` overriding a correctly wired `<label>`.

**There is no string for an empty or a failed client list, and that is the design.** The picker is **absent, not empty**, whenever it has nothing to offer — an empty list, a failed `GET /manage/floor/clients`, or a boutique before its first check-in — and the claim proceeds anonymously (spec's states table, `design.md` §3.1). A `<select>` with zero real options is a dead control that looks live, and a message explaining why the picker is missing would be an explanation for the ordinary early-morning tile.

⚠ **Parked, not blocking (spec D16, restated here because it is a copy-visible consequence):** `/manage/bookings` is owner + shift_manager, so in v1 only those two roles can check anybody in. A boutique whose **reception** role does the arrivals will see an empty client list all day and every claim will render `rooms.anonymous`. That is F34's gate, not F36's, and the remedy is F34 widening its check-in route — not a string here.

## 8. Interpolations, and which bidi helper each one takes

The two shipped helpers are `isolateLtr` and `isolateBidi` (`lib/booking.tsx`). Each splits a translated string around **one** value and returns a `ReactNode`, so **they cannot be chained** — a sentence carrying two interpolated values has no shipped way to isolate both. That constraint is why `design.md` §3.4 states the deck-wide rule *"wherever a value can be its own element, it is"*, and why **no string in this deck interpolates twice.**

| Value | Kind | Helper | Why |
|---|---|---|---|
| `{{minutes}}` | numeric run | **`isolateLtr`** → `<bdi dir="ltr">` | A digit run inside an RTL sentence. The one string is `rooms.elapsed` |
| `{{name}}` | a staffer's display name | **`isolateBidi`** → bare `<bdi>` | ⚠ **Never `isolateLtr`.** `dir="ltr"` on «נועה לוי» reverses its words, and it is the bidi defect that *looks deliberate* (F57's **F-11**). The browser resolves each name's own direction, which is exactly what is wanted when the value may be Hebrew, Arabic or Latin |
| `{{room}}` | a user-typed room label | **`isolateBidi`** → bare `<bdi>` | Same reasoning. A boutique may type «הבמה» or «VIP Room» and the panel cannot know which |
| `{{dress}}` | a user-typed dress name | **`isolateBidi`** → bare `<bdi>` | Same |
| `{{client}}` | — | **no interpolation exists** | The client's name is **always its own element** beside `rooms.clientLabel` (§2), never interpolated into a sentence. This is what lets `design.md` §6.2 replace spec D17's `rooms.occupancyLine` with three sibling fragments, and it is why the feature needs no third helper |

**Four contexts take NO treatment at all, and each is a different reason:**

| Context | Keys | Why nothing is needed |
|---|---|---|
| `aria-label` | `rooms.claimAria`, `rooms.releaseAria`, `rooms.handoverAria`, `rooms.addDressAria`, `rooms.removeDressAria` | An `aria-label` takes no markup, so there is nothing rendered to reorder. `booking.tsx`'s own comment says so |
| `<option>` text | `rooms.handoverOnBreak` | An `<option>` takes no markup either. The value is first, which is safe because the whole remainder is Hebrew and the neutral em-dash between them resolves to the paragraph direction |
| a `Select`'s `label` prop | `rooms.clientPick` | ⚠ **Typed `string` (`Select.tsx:6`), so isolation is IMPOSSIBLE, not merely omitted.** The value therefore goes **last**, where a direction flip has nothing after it to reorder past. | a `Modal`'s `title` prop | `rooms.dressTitle`; and `rooms.deleteConfirm`, which is why it lost its interpolation | ⚠ **Typed `string` (`Modal.tsx:10`), same impossibility.** `rooms.dressTitle` puts the value last and is safe; `rooms.deleteConfirm` could not, so its value moved into `children` as its own element (§5.1) |
